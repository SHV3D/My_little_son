# Технический дизайн и спецификация приложения «My little son»

## 1. Обзор и цели системы
«My little son» — мобильное веб-приложение (PWA) с автономным Node.js бэкендом, предназначенное для родителей малыша (мамы и папы). Приложение решает следующие ключевые задачи:
1. **Фиксация сна ребенка в реальном времени в 1 тап** (статусы «Бодрствует» и «Спит», шторка быстрого ввода времени или выбор «Сейчас», ручной ввод и редактирование задним числом).
2. **Динамический пересчет и умные рекомендации на остаток дня**: на основе фактических снов приложение адаптивно вычисляет, сколько еще раз ребенку спать сегодня, во сколько укладывать и по сколько минут, а также во сколько разбудить, чтобы не сдвинулся ночной отбой.
3. **Настройки режима**: возможность матери указать целевое число снов, интервал бодрствования, целевое суммарное время дневного сна и желаемое время ночного укладывания, с автоматической проверкой сходимости графика и пресетами по возрасту.
4. **Календарь и аналитика прошлых дней**: просмотр каждого дня месяца с цветовыми индикаторами выполнения нормы, суточным таймлайном (07:00–21:00) и детальными карточками всех снов.
5. **Мгновенная синхронизация между мамой и папой**: статус и настройки ребенка синхронизируются через локальный/сетевой WebSocket в реальном времени.
6. **Дизайн и эргономика**: строгое соответствие обновленной дизайн-системе **Bento Natural (Лес и Шалфей)** из файла `My little son (1).html` со шрифтом **Geologica**, палитрой (`#ECEEE6`, `#23372A`, `#D4F27A`, `#FFFFFF`) и мягкими пружинящими анимациями (60fps).

## 2. Архитектура и стек технологий

### 2.1. Клиентская часть (Frontend PWA)
* **Фреймворк:** React 18, TypeScript, Vite.
* **Стилизация & Дизайн:** Попиксельная верстка по макетам `My little son (1).html`, адаптивная сетка Bento Grid, шрифт Geologica (поддерживает кириллицу), Lucide Icons / SVG-иконки из макета.
* **Анимации:** Мягкие CSS transitions и Framer Motion / spring animations для шторки времени, плавное переключение карточек и состояний «Бодрствует ↔ Спит», плавный анимированный прогресс-бар и столбиковый индикатор бодрствования (7 делений).
* **Хранение данных на клиенте:** IndexedDB / LocalStorage для мгновенного отклика (Optimistic UI) и полной работоспособности офлайн.
* **PWA:** Манифест (`manifest.json`) и Service Worker для добавления иконки на домашний экран iOS / Android и полноэкранного режима без рамок браузера.

### 2.2. Серверная часть (Backend & Sync)
* **Среда выполнения:** Node.js, Express, TypeScript.
* **База данных:** SQLite (`better-sqlite3` или `sqlite3`), хранящаяся локально в файле `data/my_little_son.db` (zero-config, без внешних облачных зависимостей).
* **Синхронизация в реальном времени:** WebSocket сервер (`ws`), рассылающий широковещательные события при любых действиях одного из родителей.
* **Аутентификация:** Сессии / JWT, хэширование паролей (`bcryptjs`), поддержка семейных инвайт-кодов (например, `7K4-Q9M`).

## 3. Схема базы данных (SQLite)

```sql
-- Таблица семей (группа для мамы и папы)
CREATE TABLE families (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  invite_code TEXT UNIQUE NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Таблица пользователей
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  family_id TEXT NOT NULL REFERENCES families(id),
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  name TEXT NOT NULL,
  role TEXT NOT NULL CHECK(role IN ('Мама', 'Папа', 'Другое')),
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Таблица профиля ребенка
CREATE TABLE children (
  id TEXT PRIMARY KEY,
  family_id TEXT NOT NULL REFERENCES families(id),
  name TEXT NOT NULL,
  birth_date DATE,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Таблица настроек режима сна (привязаны к ребенку)
CREATE TABLE child_settings (
  id TEXT PRIMARY KEY,
  child_id TEXT UNIQUE NOT NULL REFERENCES children(id),
  naps_per_day INTEGER NOT NULL DEFAULT 3,
  wake_interval_min_minutes INTEGER NOT NULL DEFAULT 150, -- 2 ч 30 мин
  wake_interval_max_minutes INTEGER NOT NULL DEFAULT 180, -- 3 ч 00 мин
  total_wake_minutes INTEGER NOT NULL DEFAULT 600,         -- 10 ч 00 мин
  total_day_sleep_minutes INTEGER NOT NULL DEFAULT 200,    -- 3 ч 20 мин
  target_bedtime TEXT NOT NULL DEFAULT '20:30',
  typical_wakeup_time TEXT NOT NULL DEFAULT '07:00',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Таблица событий сна
CREATE TABLE sleep_events (
  id TEXT PRIMARY KEY,
  child_id TEXT NOT NULL REFERENCES children(id),
  date TEXT NOT NULL, -- Формат YYYY-MM-DD
  event_type TEXT NOT NULL CHECK(event_type IN ('WAKEUP', 'NAP', 'NIGHT_SLEEP')),
  nap_number INTEGER, -- 1, 2, 3...
  start_time DATETIME NOT NULL,
  end_time DATETIME, -- NULL если ребенок спит прямо сейчас
  duration_minutes INTEGER, -- вычисляется при завершении сна
  recorded_by_user_id TEXT REFERENCES users(id),
  recorded_by_name TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT 'MANUAL', -- 'NOW', 'OFFSET', 'RETROACTIVE'
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 4. Алгоритм адаптивных рекомендаций сна

Движок рекомендаций функционирует как на сервере, так и на клиенте (для мгновенного офлайн-расчета):

### 4.1. Входные параметры
* $N_{target}$ — целевое количество снов (например, 3).
* $[W_{min}, W_{max}]$ — диапазон интервала бодрствования (например, $150–180$ мин).
* $S_{target}$ — целевое суммарное время дневного сна (например, $200$ мин).
* $T_{bed}$ — желаемое время ночного укладывания (например, `20:30`).
* $T_{wake}$ — ориентир утреннего подъема (`07:00`) или фактический подъем за сегодня.
* $T_{now}$ — текущее астрономическое время.
* Список уже завершенных снов сегодня и текущий активный сон (если есть).

### 4.2. Расчет в режиме «Ребенок бодрствует»
1. **Текущее бодрствование:**
   $$D_{awake} = T_{now} - T_{last\_wake}$$
   Отображается крупным шрифтом `64px` в формате `ч:мм` (например, `2:10`).
   В карточке анимируется вертикальный 7-ступенчатый столбиковый индикатор:
   $$\text{Step} = \min\left(7, \max\left(1, \left\lfloor \frac{D_{awake}}{W_{max}} \times 7 \right\rfloor \right)\right)$$
2. **Время следующего сна:**
   $$T_{next\_nap\_start} = T_{last\_wake} + W_{min} \dots T_{last\_wake} + W_{max}$$
   Подсказка: *«через ~X мин, в ЧЧ:ММ»*.
3. **Расчет оставшихся снов:**
   * Считается выполненный дневной сон: $S_{done} = \sum D_i$.
   * Остаток целевого дневного сна: $S_{remain} = \max(0, S_{target} - S_{done})$.
   * Количество оставшихся дневных снов: $K_{remain} = \max(0, N_{target} - K_{completed})$.
   * **Распределение длительности оставшихся снов:**
     * Если $K_{remain} = 2$:
       - Сон 2 планируется как основной длинный сон ($D_{nap2} \approx \min(90, S_{remain} - 35)$ мин).
       - Сон 3 планируется как поддерживающий короткий «мостик» ($D_{nap3} \approx 30–35$ мин) перед ночным сном.
     * Если $K_{remain} = 1$:
       - Единственный оставшийся сон планируется на оставшееся время сна $S_{remain}$ с оглядкой на то, чтобы от окончания сна до $T_{bed}$ оставался интервал не менее $W_{min}$.
4. **Адаптивная обработка сдвигов (Schedule Crunch):**
   * Если фактический день затянулся и времени до целевого отбоя $T_{bed}$ недостаточно для всех плановых снов и интервалов:
     - **Шаг 1:** Длительность последнего сна укорачивается до минимально допустимого мостика (20–25 мин).
     - **Шаг 2:** Если даже при этом ребенок не успевает отгулять $W_{min}$ перед ночью, система предлагает пропустить последний сон и перенести ночной отбой чуть раньше (на 15–20 мин), выводя на карточке поясняющий статус: *«Сон сокращен, чтобы не сместить ночь»*.

### 4.3. Расчет в режиме «Ребенок спит»
1. **Таймер сна:**
   $$D_{sleep} = T_{now} - T_{sleep\_start}$$
   Отображается как `ч:мм` (например, `0:25`) в крупной карточке `64px`.
2. **Критическое время подъема (Разбудить до):**
   $$T_{wake\_deadline} = T_{bed} - \sum(\text{минимальные интервалы бодрствования до ночи}) - \sum(\text{длительности последующих снов})$$
   На лаймовой карточке выводится: *«Разбудить до 14:52, иначе сдвинется отбой»*.
3. **Прогноз отбоя:**
   Если сон превышает плановую длительность, приложение автоматически пересчитывает ночной отбой: *«Ночной сон: 20:25 (пересчитано)»*.

### 4.4. Проверка сходимости настроек (Settings Sanity Check)
Формула проверяет согласованность параметров:
$$T_{day\_length} = T_{bed} - T_{wake}$$
$$T_{required} = S_{target} + (N_{target} \times W_{avg})$$
* Если $|T_{day\_length} - T_{required}| \le 30$ мин: статус валидации **зеленый** (*«3 сна × интервал 2:30–3:00 при отбое в 20:30 — план сходится»*).
* Если $T_{required} > T_{day\_length} + 30$ мин: подсказка родителям о перегрузе дня (*«При таких интервалах отбой сдвинется. Рекомендуем сократить дневной сон или число снов»*).

## 5. Спецификация экранов UI (Strict `My little son (1).html` Bento)

### Экран 1: «Сегодня — бодрствует» (`01_today_awake.html`)
* **Шапка:** Дата (`Среда, 30.09`), плашка синхронизации `Мама · Папа` с белым фоном.
* **Главный Bento-блок (`#23372A`):**
  * Плашка статуса: лаймовый бейдж `#D4F27A` «Бодрствует», правее «с 10:55».
  * Крупный таймер `64px` (`2:10`).
  * Справа — 7-сегментный столбиковый индикатор прогресса бодрствования.
  * Текст: «интервал 2:30–3:00».
* **Сетка Bento-метрик:**
  * Лаймовая карточка `#D4F27A`: «Следующий сон: 13:25», подпись «через ~20 мин · 1 ч 30 мин».
  * Белая карточка `#FFFFFF`: «Ночной сон: 20:30», «цель отбоя».
  * Белая карточка `#FFFFFF`: «Днём: 1:15 / 3:20» с прогресс-баром.
  * Белая карточка `#FFFFFF`: «Осталось снов: ещё 2 из 3» с 3 квадратиками статуса.
  * Двойная белая карточка: «Потом: сон 3: 17:25 – 18:00 · 35 мин».
* **Нижняя кнопка действия:** Хвойная `#23372A` кнопка с лаймовым полумесяцем: **«Уснул»**.

## 6. План тестирования и критерии приемки

1. **Тестирование алгоритма рекомендаций (Unit-тесты):**
   * Расчет интервалов и времени следующего сна при типовом режиме.
   * Адаптивное сжатие последнего сна («мостика») при запаздывании.
   * Пересчет времени ночного сна при затягивании дневного сна.
   * Проверка валидатора настроек на корректные и некорректные диапазоны.
2. **Тестирование API и базы данных (Integration-тесты):**
   * Регистрация и авторизация мамы и папы.
   * Вход по семейному инвайт-коду.
   * CRUD операций со снами (добавление, редактирование задним числом, удаление).
   * Сохранение и получение настроек ребенка.
   * Генерация данных календаря по месяцам.
3. **Тестирование реального времени (WebSocket):**
   * Изменение статуса «Уснул» мамой приводит к мгновенному обновлению интерфейса папы без перезагрузки страницы.
4. **Тестирование UI и PWA:**
   * Проверка верстки на мобильных разрешениях (375px, 390px, 414px, 430px) и соответствия шрифтов/цветов макетам `My little son (1).html`.
   * Плавность открытия шторки и анимаций переходов.
   * Корректная работа таймеров в фоновой вкладке и при пробуждении устройства.
