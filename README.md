# My little son — Умный трекер и планировщик сна ребенка1

Полнофункциональное веб-приложение (PWA) для ведения и адаптивного планирования режима дневного и ночного сна ребенка с поддержкой совместного доступа для родителей в реальном времени.

Визуальный дизайн строго соответствует концепции **Bento Natural («Лес и Шалфей»)** на базе шрифта **Geologica**.

---

## Ключевые возможности

1. **Экран «Сегодня — бодрствует»**:
   - Крупный счетчик времени бодрствования с 7-сегментной шкалой усталости.
   - Bento-карточки следующего сна, цели отбоя, прогресса сна за день и оставшихся снов.
   - Быстрое действие «Уснул» с возможностью подтверждения в один клик («Сейчас») или выбора времени со сдвигом (`−5`, `−10`, `−15`, `−30 мин`).

2. **Экран «Сегодня — спит»**:
   - Крупный счетчик текущего сна со статусом и временем засыпания.
   - Bento-карточка дедлайна подъема («Разбудить до... иначе сдвинется отбой»).
   - Пересчитанное время ночного отбоя.
   - Список записей за день с указанием автора (Мама / Папа) и кнопка добавления сна задним числом.
   - Кнопка «Проснулся».

3. **Математический движок адаптивного сна (`shared/sleepEngine.ts`)**:
   - Динамический пересчет цепочки оставшихся снов.
   - Сжатие снов при дефиците времени и выделение мостикового сна (bridge nap, от 20 мин).
   - Защита ночного сна: перенос отбоя только при невозможности уложить все сны без переутомления.
   - Проверка сходимости настроек режима (Sanity check) относительно 24-часовых суток.

4. **Экран «Календарь»**:
   - Сетка месяца с индикаторами выполнения нормы дневного сна (темно-зеленый — норма, янтарный — меньше нормы).
   - Детальный таймлайн суток (07:00–21:00) с точной визуализацией дневных снов и ночного отбоя.
   - Сводные карточки за выбранный день (длительность, отклонение от нормы, число снов).

5. **Экран «Настройки»**:
   - Редактирование имени ребенка.
   - Быстрые возрастные пресеты (3–5 мес, 6–8 мес, 9–11 мес, 12–18 мес).
   - Степлеры дневных снов, целевой отбой, интервалы бодрствования и сумма дневного сна.
   - Живой баннер сходимости графика с подсказками по балансировке режима.
   - Секция семьи с генерацией и копированием инвайт-кода (`7K4-Q9M`).

6. **Синхронизация в реальном времени (WebSocket)**:
   - Автоматическое обновление данных между устройствами родителей.
   - Индикатор присутствия («Мама · Папа» с зеленым огоньком онлайна).

7. **Авторизация и безопасность**:
   - Регистрация мамы с созданием новой семьи.
   - Подключение папы по коду приглашения.
   - Безопасное хранение паролей (bcrypt) и JWT-авторизация.

8. **PWA и мобильный UX**:
   - Манифест PWA и Service Worker для кэширования статики.
   - Поддержка автономного режима (standalone), safe-area для iOS.
   - Плавные пружинные анимации 60fps.

## Запуск проекта

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск в режиме разработки
Команда запускает одновременно бэкенд на порту `3001` и Vite-клиент на порту `5173`:
```bash
npm run dev
```
Откройте в браузере: `http://localhost:5173`

### 3. Запуск тестов
Полный набор тестов (unit, API, WebSocket, sleep engine):
```bash
npm test
```

### 4. Сборка для продакшена
```bash
npm run build
```

### 5. Автономный запуск собранного приложения
Сервер на Node.js раздает и REST API/WebSocket, и статические файлы фронтенда:
```bash
npm start --workspace=server
```
Приложение доступно по адресу: `http://localhost:3001`

## PWA / Push / Биометрия: эксплуатация

Домен продакшена: `son.shved.su` (Beget).

### HTTPS-only

Сервер принудительно редиректит на HTTPS: любой запрос с `X-Forwarded-Proto: http` (или без TLS) к non-localhost хосту получает `301` на `https://<host><url>` и далее отдаёт заголовок `Strict-Transport-Security`. Исключение — только `localhost`/`127.0.0.1` (режим разработки).

### Push: cron-диспетчер

Доставка push-уведомлений («Пора спать» / «Пора будить») происходит по дёргыванию `POST /api/push/dispatch`. У сервера есть собственный внутренний таймер (каждые 60 секунд, пока процесс жив), но на проде это дублируется внешним cron в панели Beget — он не зависит от того, жив ли Node-процесс:

```
* * * * * curl -s -m 50 https://son.shved.su/api/push/dispatch -H "X-Cron-Key: <ключ>" >/dev/null 2>&1
```

Роут проверяет заголовок `X-Cron-Key` и без правильного значения отвечает `403`. Значение ключа — одно из:

1. **Задать явно**: переменная окружения `PUSH_CRON_KEY` в настройках Passenger-приложения на Beget. Если она задана — используется всегда, автогенерация не включается.
2. **Автогенерация**: если `PUSH_CRON_KEY` не задан, сервер при первом обращении создаёт случайный ключ (`crypto.randomUUID()`) и сохраняет его в таблице `app_config` под ключом `push_cron_key`. Достать его из базы:
   ```sql
   SELECT value FROM app_config WHERE key='push_cron_key';
   ```

Публичный VAPID-ключ для подписки на push отдаётся без авторизации: `GET /api/push/vapid-public-key` → `{"key":"..."}`.

### iPhone: установка и push

- Web push на iOS работает **только** в приложении, установленном на домашний экран как PWA (standalone), и только на **iOS ≥ 16.4**. В обычной вкладке Safari push не работает — это ограничение iOS, не баг приложения.
- Если после обновления старая установка на домашнем экране показывает белый экран (залипший старый Service Worker) — разовое решение: **удалить иконку с домашнего экрана и добавить её заново** через Safari → «Поделиться» → «На экран „Домой"». Это один раз пересоздаёт Service Worker.

### Биометрия (WebAuthn / Face ID)

Биометрический вход привязан к конкретному устройству (device-bound credential) и **не синхронизируется** между устройствами. Маме и папе нужно включить Face ID в «Настройках» отдельно на каждом своём iPhone — запись об отпечатке создаётся в `webauthn_credentials` персонально для устройства, на котором прошёл enroll.

### Смоук-проверка после деплоя

```bash
curl -sS -o /dev/null -w "%{http_code}\n" -H "X-Forwarded-Proto: http" http://son.shved.su/   # ожидаем 301
curl -sS -o /dev/null -w "%{http_code} %{content_type}\n" https://son.shved.su/sw.js           # ожидаем 200 javascript
curl -sS https://son.shved.su/api/push/vapid-public-key                                        # ожидаем {"key":"..."}
```

Подробный ручной чек-лист для проверки на реальном iPhone (install, push при закрытом приложении, Face ID) — см. [`docs/manual-verification-iphone.md`](docs/manual-verification-iphone.md).
